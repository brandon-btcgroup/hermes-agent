# Hermes 0.16.0 cutover runbook (AI server)

The `feat/simplex-0.16` branch is built, tested (123 SimpleX tests pass, footgun
clean), and pushed to the fork. This runbook is the **Phase 8** steps to run **on
the AI server** to go live with 0.16.0 (desktop app + SimpleX together). Production
stays on the old `feat/simplex-plugin` branch until you run the cutover, and
rollback is instant.

> On the AI server, the fork remote is `fork` (brandon-btcgroup) and `origin` is
> NousResearch. On the dev box those are `origin` and `upstream` respectively.

## 1. Pre-cutover: migrate the server `.env`

Edit `~/.hermes/.env`:

- **Rename** (0.16.0 renamed these):
  - `SIMPLEX_HOME_GROUP_ID`   → `SIMPLEX_HOME_CHANNEL`
  - `SIMPLEX_HOME_GROUP_NAME` → `SIMPLEX_HOME_CHANNEL_NAME`
- **Remove** `SIMPLEX_GROUP_IDS` — it has **no 0.16.0 equivalent**. Groups are now
  auto-detected per inbound message; access is gated only by the user allowlist.
  Make sure the senders you want are in `SIMPLEX_ALLOWED_USERS` (or set
  `SIMPLEX_ALLOW_ALL_USERS=true` on a trusted setup).
- **Revert debug leftovers** from the prior session if present:
  `SIMPLEX_ALLOWED_USERS=Brandon,TjdJQnpkazF2MFdpTXhNYw==` and
  `SIMPLEX_ALLOW_ALL_USERS=true` (set these to your intended production values).
- **Keep / set** the file-media vars (now supported again via this branch):
  - `SIMPLEX_FILE_DIR` = host path bind-mounted to the daemon's files folder
  - `SIMPLEX_DAEMON_FILES_FOLDER` = container path (default `/root/.simplex/files`)
- **Optional** replay tuning (defaults are fine): `SIMPLEX_REPLAY_DISABLED`,
  `SIMPLEX_REPLAY_MAX_ITEMS` (200), `SIMPLEX_REPLAY_PAGE_SIZE` (50).
- **Add the desktop-app token:**
  - `HERMES_DASHBOARD_SESSION_TOKEN=<long random secret>`

Full `SIMPLEX_*` set the 0.16 adapter reads: `SIMPLEX_WS_URL`,
`SIMPLEX_ALLOWED_USERS`, `SIMPLEX_ALLOW_ALL_USERS`, `SIMPLEX_HOME_CHANNEL`,
`SIMPLEX_HOME_CHANNEL_NAME`, `SIMPLEX_FILE_DIR`, `SIMPLEX_DAEMON_FILES_FOLDER`,
`SIMPLEX_REPLAY_DISABLED`, `SIMPLEX_REPLAY_MAX_ITEMS`, `SIMPLEX_REPLAY_PAGE_SIZE`.

## 2. Cutover

```bash
cd ~/.hermes/hermes-agent          # the server's checkout
git fetch fork
git reset --hard fork/feat/simplex-0.16
uv pip install -e ".[all,dev]"     # 0.16.0 changed many deps — reinstall
# (optional but recommended: install the simplex extra explicitly)
uv pip install -e ".[simplex]"
```

Start the dashboard (this single process runs the gateway incl. the SimpleX
adapter AND serves the desktop-app WebSocket API):

```bash
hermes dashboard --host <LAN/Tailscale/VPN-IP> --port 9119
```

> **Bind only to a private interface.** Static-token mode is a shared secret with
> no per-user identity — do NOT expose it on a public 0.0.0.0. If the server must
> be reachable on an untrusted network, use OAuth instead:
> `hermes dashboard register` (needs Nous login), then `hermes dashboard --host …`.

## 3. Verify SimpleX still works on 0.16.0

- Send a multi-line message from your phone to the group → expect a complete
  multi-line reply (json send fix; no truncation).
- Have the agent send an **image** to the group → arrives with a thumbnail
  (outbound media + bind-mount).
- Send a file from your phone → the agent ingests it (inbound bind-mount).
- `hermes simplex list` → shows the active user + joined groups.

## 4. Connect the desktop app

- Install **Hermes Desktop** on your laptop (prebuilt installer, or `hermes desktop`
  if hermes is installed locally).
- Settings → Gateway → URL `http://<server-ip>:9119`, paste the
  `HERMES_DASHBOARD_SESSION_TOKEN`.
- Test/Connect → expect `/api/status` OK then a live WS session; drive a session
  end-to-end.

## 5. Rollback (if anything is wrong)

```bash
cd ~/.hermes/hermes-agent
git reset --hard feat/simplex-plugin    # old standalone fork, still intact
# restore the old .env var names: SIMPLEX_HOME_GROUP_ID/NAME, SIMPLEX_GROUP_IDS
hermes gateway restart                  # or your prior start command
```
The old branch plus the `pre-0.16-cutover` and `simplex-known-good-20260529` tags
remain as rollback anchors. Rollback also reverts the multi-line json send fix.

## Known limitations & non-blocking followups

- **Staged outbound files are not auto-deleted.** When sending media by URL or
  from a path outside `SIMPLEX_FILE_DIR`, the file is copied/downloaded into
  `SIMPLEX_FILE_DIR` and left there (immediate deletion would race the daemon's
  async read). Point `SIMPLEX_FILE_DIR` at storage you can periodically prune.
- **Compose doc image claim:** the docker-compose recipe uses
  `image: simplexchat/simplex-chat:latest` and the prose was updated to say the
  image is published. Sanity-check that tag exists / matches what your daemon
  actually runs before relying on the doc verbatim.
- **Followups (none blocking), from the final review:**
  1. Extract the outbound-media helpers into `plugins/platforms/simplex/_media.py`
     (adapter.py is ~1450 lines).
  2. `_init_replay_state` disables replay for the adapter's lifetime if
     `hermes_constants` import fails — add a clarifying comment.
  3. `_ws_client.py` (CLI) doesn't send `/_start` before `list`/`join` queries —
     fine (it has timeouts), but asymmetric with the adapter; note or add it.
  4. `SIMPLEX_WS_URL` is marked required-env yet `_standalone_send` has a localhost
     fallback — harmless inconsistency.
